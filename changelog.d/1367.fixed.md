### Fixed — `jax.jit` of `forward()` compiles for every single-device model: MSL-fed boards, NTFF far-field losses and functions with no traced input (#1367, #1354, #1364)

- `jax.jit(jax.grad(loss))` over `forward()` no longer raises
  `TracerArrayConversionError` on a board with `add_msl_port()`, or when the
  loss calls `compute_far_field` on the forward's own NTFF box (numpy `freqs`).
  An optimisation step now compiles once instead of on every call.
- `jax.jit` of a `forward()` call with no traced input (a wire-port board on
  JAX 0.6.2 raised `Evaluation rule for 'empty' not implemented`) compiles the
  solve instead of running it while tracing.
- `compute_far_field_jax` accepts a box whose frequencies are traced.
- Plain (un-jitted) results are unchanged.
