### Added — `Simulation.add_pinned_sheet`: a conductor named by node lines, so a moving mesh can be a design variable (#1199)

- A patch's resonant length is the distance between its two metal edges. You
  can now keep those edges ON node lines and move the length by stretching
  the cells between them: `sim.add_pinned_sheet(plane_index=k,
  i_range=(i_lo, i_hi), j_range=(j_lo, j_hi))` declares a thin PEC sheet by
  INTERIOR node index instead of in metres, so the conductor is the same on
  every mesh and its physical size is whatever those cells add up to. With
  that, `jax.grad` of a probe observable with respect to a `dx_profile` /
  `dy_profile` / `dz_profile` deformation runs end to end — against a
  central difference through the same function the residual falls as `h^2`
  on all four deformations tested (`+x` edge, probe on the patch plane past
  the edge, joint `x+y`, low-side edge), reaching 8e-4…4e-3 at `h = dx/64`.
- The declaration is mesh-independent by construction, so the uniform and
  non-uniform lanes realize the same nodes, and the traced and concrete
  routes realize the same nodes at every deformation. A range spanning a
  single node line is refused: one node line carries no E edge, so the metal
  would carry no current.
- Unchanged, deliberately: a sheet declared in METRES keeps its metres. On a
  mesh that is a JAX tracer its corners cannot be read off the node line, so
  it is still refused with the same message — interpreting a metric
  declaration against some other lattice would move the metal silently.
- New public surface: `Simulation.add_pinned_sheet`,
  `rfx.materials.thin_conductor.PinnedSheet` / `pinned_sheet_spec` /
  `pinned_sheet_realized` (the realized plane and edge positions in metres,
  read from the grid's own node line), and
  `rfx.boundaries.pec.SheetSpec.from_node_ranges`.
