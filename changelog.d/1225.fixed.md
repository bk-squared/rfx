### Fixed — a gradient step on a board fed by a wire port can be compiled once: `jax.jit(jax.value_and_grad(...))` over `forward()` now traces, and `rfx.optimize(jit=True)` compiles once per call instead of on every iteration (#1225)

- An un-jitted `jax.value_and_grad` over `forward()` compiles the whole solve
  again on every call; `jax.jit` removes that. On a model with a wire port
  (`add_port(..., extent=...)`) the jitted step failed while tracing — on the
  uniform lane when the model had a conductor, on the graded-mesh lane always
  — because the port's set-up reads the realized PEC edge mask and the cell
  sizes on the host. For such a model `forward()` now evaluates its set-up at
  trace time when it is staged. Every other model traces exactly as before.
- `rfx.optimize(..., jit=True)` wraps `jax.value_and_grad` in `jax.jit` once
  per call. The default stays eager: an objective that reads a traced value on
  the host (a model with an MSL port, for one) cannot run under `jax.jit`.
- A plain `forward()` or `run()` call is unchanged bit for bit. A jitted value
  and gradient agree with the plain call to float32 rounding; they are not
  guaranteed to agree bit for bit (XLA compiles the whole step as one program).
