### Fixed — a magnetic-wall face is never shorted by an axis-wide PEC wall, on any entry point (#1164, #1194)

- A port whose cell sits on the node plane of a PMC face (a one-cell
  parallel-plate line with magnetic side walls, the #1164 fixture) read
  |S11| = 1.000 for every load: the axis-wide PEC wall zeroed the port's
  tangential E every step and the open end became a short. `run()` did this
  through its default `pec_axes` (all non-periodic axes); `forward()` did it
  after #1194 gave it the same default for absorber-free boxes. Now both
  read the load's reflection, 0.334 against the closed form 1/3 at 1 GHz
  (wire port; the lumped port's own defect is PR 1162's).
- The walls are now decided per FACE by one rule, `resolve_wall_faces`
  (`rfx/boundaries/pec.py`), from the grid's own boundary declaration: a
  periodic face is no wall, a magnetic face is never an electric one, a
  declared PEC face is one, and any other face (absorber, or a raw `Grid`)
  is PEC-backed unless the legacy `pec_axes` string withholds that default
  for its axis. The scan applies `apply_pec_faces` only; the axis-wide
  `apply_pec` is gone from the step, and the GPU coefficient bake takes the
  same face set. The grid carries the spec's PEC faces for the string
  spelling too, so `forward()`'s closed-box special case (#1194) is gone.
- Unchanged elsewhere: `run()` keeps the PEC backing on absorber axes and
  `forward()` keeps withholding it, exactly as before (the two differ by
  2e-7 of the field on a CPML box — pre-existing, now written down).
