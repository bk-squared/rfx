### Fixed — preflight checks read the cell at their own site, not the boundary cell (#1209)

- A check that counts cells or measures a thickness has to use the cells where
  it looks. Seven sites used the grid's boundary cell instead, so on a graded
  mesh they judged the wrong place (gap G17, issue #810).
- The port-on-reflector-face tolerance is half a cell AT THAT FACE. It took the
  boundary scalar on x and y whatever the mesh did, and on z it took the
  profile's leading entry for BOTH faces, so a port on z_hi was judged against
  z_lo's cell.
- The CPML z-thickness advisory measures the cells the absorber sits on. It
  summed the first `max(lo, hi)` interior cells, which is neither face's
  absorber, and reported the hi face from the lo end. The absorber on a face is
  copies of that face's boundary cell, so its thickness is that cell times that
  face's own layer count; the thinner ABSORBING face is reported. A face that
  allocates no absorber (PEC, PMC, periodic) is not measured as zero thickness,
  which would have brought back the #647 false positive.
- The non-uniform limitation family was gated on "was a z profile given". A mesh
  profiled only on x or y skipped every check in it, including the TFSF support
  check whose auxiliary line runs along x. It is now gated on the same property
  that picks the non-uniform grid builder, read off the resolved mesh.
- The MSL source-fringing standoff is a length, about five substrate
  thicknesses, and the cell count is that length on the runway's own cells at
  the port. A span that crosses a grading ramp is refused with the reason
  rather than answered, because a count in cells does not name one distance
  there.
- Nothing moves on a uniform mesh: the committed preflight report snapshot,
  which pins advisory text, code, severity and emission order across 74 cases,
  is byte-unchanged.
- The per-face CPML thickness the MSL and waveguide clearance advisories use
  as a calibrated buffer summed the leading z profile entries for BOTH faces.
  On a profile whose ends differ 5x it called the fine face's absorber five
  times its realized thickness. It is now that face's boundary cell times that
  face's layer count, and the mesh advisory reads its z number from the same
  function instead of computing its own, so preflight reports one thickness
  for one absorber.
- The absorber proximity band is two cells wide measured inward from where the
  absorber begins, so the cells it covers are that face's. It used the boundary
  scalar, which on a board with 200 um cells at z_hi and a 1 mm scalar quoted a
  2 mm band for a face whose cells are a fifth of it.
- The microstrip checks read the same standoff as the S-parameter routing
  check (issue #823's invariant): the advertised compliant interval's lower
  edge, the explicit-offset advisory and the realized probe distance all count
  the runway's own cells at the port, and a standoff that crosses a grading
  ramp is refused by every one of them rather than answered. The explicit-offset
  advisory used to print `n_probe_offset` times the cell at the feed for the
  realized distance, and a cell-count remedy derived the same way; on a 254 um
  board whose runway ramps 254 -> 127 um at ratio 1.25, offset 4 read 812.8 um
  where the grid realizes 622.8 um, and the advertised remedy of 6 cells
  realizes 876.8 um, 31 % short of the 1.270 mm the fringing needs. Where the
  cells are equal it still reports the floor, and the distance it quotes is now
  read off the probe ladder the extractor itself uses.
- The compliant-offset interval counts the whole probe ladder, not just the
  standoff, so a port sitting in a uniform runway whose deepest probe runs out
  over a ramp is refused too. The distance it inverts runs from the node the
  grid stamps the feed on, where every candidate ladder starts.
- The grid stamps an MSL port's source and probe ladder on the node nearest
  the declared feed, and these checks now read the cells on the launch side
  of that node: above it for a forward port, below it for a backward one. A
  feed declared with the same literal as a mesh interface lands a few
  1e-18 m to one side of it, and is on that node. A span stops at a node it
  touches to within 1e-3 of a cell, and cells are one size when they agree
  to 1e-9 relative, the two tolerances the S-parameter reference-span check
  already used, now one shared rule; a runway built as `np.diff` of node
  coordinates is one zone.
- An automatic `n_probe_offset` on a runway finer than the boundary cell.
  `add_msl_port` counts the 5·h_sub standoff in the boundary cell, so on a
  127 um runway under a 254 um boundary cell it stores 5 cells, which puts
  probe 0 635 um from the source where the fringing needs 1.270 mm. The
  advisory says the automatic choice falls short there and names the explicit
  offset instead of saying to leave it None, the setting that chose 5; the
  S-parameter routing check says the same. "Leave it None" is offered only
  where the automatic floor clears the runway. The automatic floor itself is
  unchanged.
- TFSF along a graded x. The runner builds the 1-D incident line on the
  boundary cell while the 3-D x axis is graded, so the wave the TFSF planes
  inject does not match the wave the grid carries to them, and the difference
  leaks into the scattered-field region. With no scatterer, a +x line graded
  1 / 0.5 / 1 mm put 0.6 of the total-field peak outside the box, against
  1e-5 or less on uniform 1 mm cells and with only y graded. `nonuniform_tfsf`
  now warns whenever the TFSF axis is graded, at normal incidence too, and
  stays silent when only y or z is graded. The runner is unchanged.
