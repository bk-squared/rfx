### BREAKING — the single-plane coaxial S-matrix lane is removed, with the geometry helper and termination builders only it used (#1212)

- `Simulation.compute_coaxial_s_matrix(...)` and its result type
  `CoaxialSMatrixResult` (`rfx`, `rfx.api`) are gone. The method was deprecated
  with removal announced for v2.0. It read V/I on one plane of a coax stub
  closed in a PEC box, and its own docstring recorded |S11| > 1 on a lossless
  short. Its geometry helper drew the outer conductor as a σ = 1e10 S/m volume
  whose inner face sat one cell (min(dx, (b − a)/2)) inside the declared outer
  radius b; since the edge-averaged materials change (#1213) that wall is
  realized where it is drawn, so the annulus the lane solved ended one cell
  short of b all the way round.
- What to use instead: `compute_coaxial_line_reflection(termination="short" |
  "open" | "matched", dut_impedance=...)` for a one-port reflection,
  `compute_coaxial_two_port(...)` for a through line, or
  `compute_s_matrix(lane=...)`, which dispatches to either. Each is built from
  exactly one `add_coaxial_port(...)`; no lane accepts several coaxial ports.
- Also removed, because only the lane above consumed them:
  `Simulation.add_coaxial_matched_load`, `Simulation.add_coaxial_open_termination`,
  `Simulation.add_coaxial_pec_end_cap`, and from `rfx.sources` /
  `rfx.sources.coaxial_port`: `setup_coaxial_port`,
  `add_coaxial_matched_termination`, `add_coaxial_open_termination`,
  `add_coaxial_pec_end_cap`, `make_coaxial_port_source`. `add_coaxial_port`,
  the analytic TEM helpers (`coaxial_tem_*`, `coaxial_load_reflection`),
  `build_coaxial_tem_plane_source_specs` and `extract_coaxial_plane_vi_from_dft`
  stay.
- `preflight_sparameters`: the `run` and `forward` refusals for a coaxial port
  now name `compute_coaxial_line_reflection` and `compute_coaxial_two_port`;
  `calculator="compute_coaxial_s_matrix"` raises `ValueError` naming #1212
  instead of running the coaxial routing check.
- Design documents (`rfx-design-ir/v2`): `excitations.coaxial_matched_loads`,
  `coaxial_open_terminations` and `coaxial_pec_end_caps` stay in the schema and
  are always exported empty, so a document that registered none still loads. A
  document with an entry in any of them is refused with
  `UnsupportedDesignFeature` naming the removed builder and #1212.
- The scene artifact's `private_summary` no longer carries
  `coaxial_terminations`.
- Removed with it: ten `scripts/diagnostics/` scripts that could only run the
  removed geometry, the coaxial-gap openEMS step of
  `scripts/physics_gate_port_external_coaxial.yaml` (the coax-line comparison
  and readiness report in that shard stay), and the tests that exercised only
  the removed code.
