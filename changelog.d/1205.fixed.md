### Fixed — preflight checks read the cell at their own site, not the boundary cell (#1205)

- A check that counts cells or measures a thickness has to use the cells where
  it looks. Four sites used the grid's boundary cell instead, so on a graded
  mesh they judged the wrong place (gap G17, issue #810).
- The port-on-reflector-face tolerance is half a cell AT THAT FACE. It took the
  boundary scalar on x and y whatever the mesh did, and on z it took the
  profile's leading entry for BOTH faces, so a port on z_hi was judged against
  z_lo's cell.
- The CPML z-thickness advisory measures the cells the absorber sits on. It
  summed the first `max(lo, hi)` interior cells, which is neither face's
  absorber, and reported the hi face from the lo end. The absorber on a face is
  copies of that face's boundary cell, so its thickness is that cell times that
  face's own layer count; the thinner ABSORBING face is reported. A face that
  allocates no absorber (PEC, PMC, periodic) is not measured as zero thickness,
  which would have brought back the #647 false positive.
- The non-uniform limitation family was gated on "was a z profile given". A mesh
  profiled only on x or y skipped every check in it, including the TFSF support
  check whose auxiliary line runs along x. It is now gated on the same property
  that picks the non-uniform grid builder, read off the resolved mesh.
- The MSL source-fringing standoff is a length, about five substrate
  thicknesses, and the cell count is that length on the runway's own cells at
  the port. A span that crosses a grading ramp is refused with the reason
  rather than answered, because a count in cells does not name one distance
  there.
- Nothing moves on a uniform mesh: the committed preflight report snapshot,
  which pins advisory text, code, severity and emission order across 74 cases,
  is byte-unchanged.
