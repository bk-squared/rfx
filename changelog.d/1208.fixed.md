### Fixed — a multi-device run no longer keeps the whole domain on the first device of every process through time stepping (#1208)

- `sim.run(devices=...)` rasterized and staged the whole domain on the first device of
  every process and kept those arrays through the run, kept preflight's cached assembly
  alive, and gave every device slab-size zero arrays for Debye/Lorentz materials the model
  did not have. On two RTX 4090 nodes (one process per GPU) that cost 169–173 bytes per
  whole-domain cell on each GPU, against 98 for the same 2.7–5.4 M-cell boxes on one 4090,
  so splitting a model across GPUs ran out of memory before a single GPU did.
- During time stepping each device now holds only its own slab as live arrays: state is
  created on its device, material and PEC-mask slabs are staged per addressable shard, the
  whole-domain setup arrays and preflight's cached assembly are released before the loop,
  and absent Debye/Lorentz materials use one placeholder value per device. Setup still
  rasterizes the whole domain once per process. On two RTX 4090 nodes a 324 M-cell PEC box
  runs at 11.7 GB per GPU (36 bytes per whole-domain cell); the same box ran out of memory on
  two 4090 nodes without this change and on one 4090 at memory fraction 0.9, and a 476 M-cell
  box runs out of memory on one 4090 at fraction 0.95.
- Not changed: when one process drives several devices, the time loop still captures the
  material, PEC-mask, dispersion and CPML arrays, which the compiler keeps as whole-domain
  constants on every device; one process per GPU avoids it.
- Results are bit-identical to before (SHA256 of the probe trace and all six field
  components, eight models on two devices).
