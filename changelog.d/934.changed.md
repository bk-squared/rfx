### Changed — changelog entries are written as `changelog.d/` fragments instead of being appended to `CHANGELOG.md` (#934)

- Each PR now adds its own `changelog.d/<number>.<type>.md` holding exactly the
  text it used to paste under `## [Unreleased]`. Two PRs never touch the same
  file, so the conflict class that made `CHANGELOG.md` the repo's main
  merge-conflict source disappears by construction.
- `scripts/changelog/assemble.py` (stdlib only) moves the fragments under the
  `## [Unreleased …]` heading newest number first and deletes them; `--release
  X.Y.Z` then renames that heading and opens a fresh `## [Unreleased]` above
  it, which makes writing an entry into an already released section impossible.
- `.github/workflows/changelog-fragment.yml` enforces two rules on every PR: a
  change under `rfx/` must add a fragment, and `CHANGELOG.md` itself may only be
  edited by a PR labelled `release`. The existing `## [Unreleased — 2.0.0]`
  block is left exactly as it is; fragments start from here.
