### BREAKING — a Huygens (NTFF) box must sit at least one cell inside the grid on every axis; two set-ups that ran before now raise (#1159)

- Moving each face sample to the centre of its face cell (the second-order
  far-field fix in this PR) reads one index further out than the face, so
  `1 <= lo < hi <= n-1` must hold on every axis.
- A box that spans the whole domain with `cpml_layers=0` now raises a
  `ValueError` when the box is built. What to do: move each face at least one
  cell inside the domain. With an absorber (`cpml_layers > 0`) nothing
  changes — the absorber cells already provide the room, and the innermost
  one is a free-space cell (the CPML conductivity is graded to zero there).
- An NTFF box in a 2-D run (`mode="2d_tmz"`, one cell in z) now raises. It
  used to run and return an all-zero far field, because its x and y faces had
  zero width. The far-field transform needs a 3-D box.
- The message names the offending axis in cells and in metres, gives the
  range that axis can carry a face in, and points at
  `Simulation.add_ntff_box`. The subgridded runner checks its fine-grid box
  before the scan starts.
