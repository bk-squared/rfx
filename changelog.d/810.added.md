### Added — both grid classes answer for the cell at a site, not one scalar (#810)

- On a graded mesh the cell under a port, an absorber or a probe is usually
  not the cell at the domain boundary, and `grid.dx` returns the boundary
  one. A consumer that reads it injects, absorbs or counts at the wrong
  metric wherever the two differ. This is a code-structure change, not a
  physics fix: nothing a user runs today produces a different number, because
  no consumer has moved yet.
- `Grid` and `NonUniformGrid` both answer `cells(axis)`, `duals(axis)`,
  `index_of(axis, x)`, `node_of(axis, i)`, `boundary_cell(axis, side)`,
  `is_constant(axis)` and `is_traced(axis)`, with the same meaning, so a
  consumer can hold either and never branch on its type.
- `rfx/_grid_metric.py` records the convention once: the padded index origin,
  the primal and dual rules with their end entries
  (`inv_d_h[N-1] = 0`, `inv_d_e[0] = 1/d[0]`), and which metric each consumer
  is entitled to, read at each site.
- `make_nonuniform_grid` now refuses a mesh whose realized interior cells do
  not sum to the declared profile to 1e-12 m.
- `index_of` refuses a traced axis instead of answering from a nominal
  uniform mesh the solver is not running. `position_to_index` keeps that
  fallback for now; consumers still call it.
- `tests/contracts/test_grid_scalar_reads_tracker.py` counts the scalar reads
  that remain, 172 in 50 modules, and refuses to let the count grow.
