### 1.2 Meep — conda-forge `pymeep`, per-run env

- Version actually used: `validation/crossval/_22_dispersive_results/meep_lorentz.json::meep_version = 1.34.0` (same in cv23). Installed per run by `conda create -n cv22meep … -c conda-forge python=3.11 pymeep` (`scripts/vessl_cv22_dispersive_slab.yaml:66`); no image, no MPI build. The scheduled CI lane does the same with mamba (`.github/workflows/validation.yml:216`).
- MPB eigenmode solver rejects PEC — in-repo: "MEEP's MPB eigenmode solver rejects PEC (mp.metal) walls ('invalid dielectric function for MPB')" (`scripts/diagnostics/meep_coax_line_reference.py:8-9`, `scripts/diagnostics/meep_tjunction_reference.py:4-6`); upstream docs (Python User Interface): "Meep's MPB interface only supports dispersionless non-magnetic materials". Consequence: for metal-walled guides and planar lines the in-repo pattern is **power flux through a port plane with a straight-line normalization run** (magnitudes only), or **field dumps projected onto a modal/quasi-TEM template offline** for complex S (`scripts/diagnostics/wr90_port/s11_from_dumps.py`, the cv11 `MEEP_r4` column).
- No lumped/impedance-defined port (no such object in the Meep API; the repo's coax/T-junction references are flux-based for that reason). So openEMS-style `|S11|` dips of a 50 Ω feed are not reproducible in Meep; resonance f0 (harminv on a ring-down) and far field (`near2far`, 3-D) are.
- Materials: `LorentzianSusceptibility`, `DrudeSusceptibility`, `D_conductivity` (in-repo mapping `validation/crossval/comparators/dispersive_eps.py::to_meep`, pre-checked through `Medium.epsilon(f)` to 1e-9: `_22_dispersive_results/meep_lorentz.json::precheck.max_rel_err = 1.8e-15`, `_23_lossy_results/meep_tand1.json::precheck.max_rel_err = 1.6e-16`).
- Recorded pitfalls (must be carried into every new Meep leg):
  - **First-order interface term / node-count effective thickness.** Meep's `Block` without effective averaging realizes `d + a/res`; the committed ladders are first order (`_23_lossy_results/meep_ladder_summary.json::arms.tand0p1.orders.order_dR_20_40 = 1`, `_22_dispersive_results/meep_ladder_summary.json::arms.lorentz.orders.order_dT_10_20 = 0.97`); a half-pixel centre shift collapses it to the lattice level (`meep_ladder_summary.json::diagnostics.tand0p1.res40_shift_half.mean_dR_meep_tmm_gated = 0.00024` vs nominal `::arms.tand0p1.rungs.40.mean_dR_meep_tmm_gated = 0.016`); the reference is converged only one rung under the window (`_23_lossy_results/rfx.json::arms.tand0p1.meep.mean_dR_meep_tmm_gated = 0.0078` vs `::arms.tand0p1.meep.mean_window4_R = 0.01`). cv23 note §12.3, §13.2.
  - **Debye instability.** cv22 note F-B: at 10 px/cm the mapped Debye pole gives `ε_num(Nyq) = 0.486 < 1`, Meep's Courant 0.5 falls outside the 2-D limit and the run is NaN; the coupled criterion is `ε_num(Nyq) ≥ (S/S_max)²`, satisfied at 40 px/cm (`ε_num(Nyq) = 1.930`). The 10 px/cm rung is kept as the instability witness in every cv22 round (`scripts/vessl_cv22_dispersive_slab_r4.yaml:105-110`).
  - `eps_averaging` defaults to True (upstream docs); a leg meant as the staircase twin of rfx's binary rasterize path (cv17) must set it False and say so.
- Measured cost: cv22 primaries at 40 px/cm, 2-D, ~2 s each (`~/Documents/vessl-run-logs/369367257811_cv22-dispersive-r4.log:345,361,377`: "Elapsed run time = 1.93 / 1.80 / 1.81 s"); the conda env build dominates the lane wall time.

### 1.3 Palace — source-built binary on NFS, no image

- Build actually used: `tests/fixtures/msl_notch_e4/msl_stub_notch_palace_referee.json::meta.version = "58f2991-dirty"`, order 2, GPU rtx4090, from `/root/workspace/byungkwan-workspace/research/microwave-energy/palace_simulation/palace_install` with OpenMPI apt-installed per run on `nvidia/cuda:12.1.0-devel-ubuntu22.04` (`scripts/diagnostics/palace_notch_referee/vessl_palace_notch_4090.yaml`). The upstream version of that commit is not recorded anywhere in the repo.
- Upstream (awslabs/palace, latest release v0.17.0, 2026-06-29; docs `docs/src/guide/*.md` read at `main`):
  - Problem types: Eigenmode, Driven (frequency domain, adaptive sweep), **Transient** (lumped-port or surface-current excitation, port V/I time histories to `port-V.csv`/`port-I.csv`), Electrostatic, Magnetostatic, BoundaryMode (v0.17).
  - Ports: `LumpedPort` (multi-element), `WavePort` ("2D boundary mode eigenproblem on each wave port boundary … arbitrary cross sections"; supports PEC/PMC/impedance/absorbing/conductivity in the 2-D solve; **outer boundary only**; polarity pinned by `VoltagePath`/`PolarityAttributes`), `FloquetPort` (v0.17; periodic structures, oblique incidence, diffraction orders), mixed lumped/wave S-parameters (v0.17).
  - Boundaries: PEC, PMC, Impedance, RationalImpedance, Absorbing (first order; second order frequency-domain only), Conductivity, Periodic + Floquet (v0.14). **"Perfectly matched layer (PML) boundaries … are not yet implemented"** (`docs/src/guide/boundaries.md:72-76`).
  - Materials (`docs/src/guide/model.md:62-72`): relative permittivity, permeability, loss tangent, conductivity, London depth (scalar or symmetric-matrix). **No Debye/Lorentz/Drude pole model**; permittivity is a constant over a sweep.
  - Far field: v0.15+ Stratton-Chu extraction on an external integration surface in Driven/Eigenmode (`docs/src/features/farfield.md`); output `r·E(θ,φ)`.
  - 2-D meshes across all simulation types: v0.17 (release notes, PR 657/727).
  - No plane-wave / total-field-scattered-field source for a finite scatterer: the only excitations are ports, Floquet ports (periodic unit cells), and surface currents (`guide/boundaries.md`, `guide/problem.md:103-124`).
- Recorded pitfalls: lumped ports leak, so only zero **frequencies** are refereed, not `|S|` levels (`tests/fixtures/sheen_lpf_e4/sheen_lpf_palace_referee.json::meta.port_note`); an LC/2 mesh OOMs the 24 GB rtx4090, the √2 "mid" mesh is the convergence witness (`msl_stub_notch_palace_referee.json::meta.vessl_runs.failed_lanes`); wave-port S-parameters are referenced to the port face, so the cv11 Palace phase columns carry an un-corrected `2·β·50 mm` / `β·100 mm` offset against the FDTD monitor planes (`validation/crossval/11_waveguide_port_wr90.py:753-762`); **graded mesh**: the only Palace-vs-NU evidence is graded-dy ratio 2.0 (`tests/fixtures/waveguide_nu_broad_e4/waveguide_wr90_nu_flux_broad_e4_comparison.json`, cv24 note §10, `docs/guides/sparameter_support_matrix.md:622` "graded-dy only, so dz-graded results are dispatch-correct and unvalidated") — a Palace leg on an rfx graded mesh is evidence for that grading direction/ratio only, and Palace's own tetrahedral grading near PEC edges must be refined by the √2 witness, not assumed.
- Measured sizes: notch referee coarse 143,812 tets / 968,238 DOF, 101 frequency points 2–7 GHz; Sheen coarse 140,039 tets / 924,257 DOF, 81 points; mid meshes ~2.5 M DOF (`::meta.mesh` blocks of the two fixtures). Wall time was not recorded in either fixture; the VESSL run ids are `369367246161/8`, `369367248550/8`.
