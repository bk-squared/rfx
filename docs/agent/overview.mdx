This is the entry point for an AI agent that builds, runs or reviews an rfx
simulation. The reviewed agent pages are also available as Markdown in the
[LLM index](/rfx/llms.txt), next to the typed API inventory and the support
contracts.

## The five steps

Every rfx result goes through the same five steps. Do them in order, and do not
report a number until step 5 is done.

1. **Declare the model.** Domain and mesh, boundaries, materials, conductors,
   sources and ports, and the outputs you need, all before the run.
   Pages: [Domain and mesh](/rfx/model/domain-mesh/),
   [Boundaries](/rfx/model/boundaries/), [Materials](/rfx/model/materials/),
   [Conductors](/rfx/model/conductors/), [Sources](/rfx/model/sources/),
   [Ports](/rfx/model/ports/), and [which port or source to use](./port-selection).
2. **Check the model on the grid.** Read what the grid built against what you
   drew (`sim.preflight()`, `sim.fidelity_report()`), and expect a refusal for
   any input the solver path does not implement.
   Pages: [Check the model on the grid](/rfx/check/model-on-grid/),
   [Refused inputs](/rfx/check/refusals/).
3. **Run.** `run()` for analysis, `forward()` for gradients; a fixed number of
   steps in closed structures and convergence studies.
   Pages: [run() and forward()](/rfx/run/run-and-forward/),
   [Memory and speed](/rfx/run/memory-and-speed/),
   [Multi-device runs](/rfx/run/multi-device/).
4. **Measure.** S-parameters, probes and fields, far field, resonances.
   Pages: [S-parameters](/rfx/measure/s-parameters/),
   [Probes and fields](/rfx/measure/probes-and-fields/),
   [Far field and RCS](/rfx/measure/far-field-and-rcs/),
   [Resonances](/rfx/measure/resonances/).
5. **Check the result.** Was the run long enough for every frequency you read,
   is the mesh converged over at least three meshes, and does the result
   agree with its reference on the stated terms. A gradient needs its own check from a longer run.
   Pages: [Is the run long enough?](/rfx/check/simulation-time/),
   [Is the mesh fine enough?](/rfx/check/mesh-convergence/),
   [When does a result agree with a reference?](/rfx/check/agreement/),
   [Checking a gradient](/rfx/check/gradients/),
   [Simulation time for gradients](/rfx/check/gradient-simulation-time/).

For design work, [Design regions](/rfx/design/design-regions/) says what
`forward()` can differentiate with respect to.

## Rules for an agent

1. **Check support before you claim physics.** The
   [support page](/rfx/support/) gives each feature one status: supported,
   limited, experimental, not documented or unsupported. Say which one applies
   to every feature your result uses.
2. **Start from an example.** Adapt the closest file in `examples/` or the code
   on the relevant page before writing your own loop.
3. **Read the refusal.** A refused input raises before the first step with the
   reason and the way through. Follow it; do not work around it with a
   lower-level call that skips the check.
4. **Judge a trend, not one number.** A result is reported with the curve over
   frequency, how it moves over at least three meshes or simulation times, and
   the reference it is compared with.
5. **Keep outputs out of the repository.** Plots, Touchstone files, snapshots
   and reports go in an output directory.

## A safe prompt

```text
Use rfx. Declare the model, read preflight and the fidelity report, and run the
smallest case first. Report each feature's status from the support page, the
check of whether each run was long enough for every frequency it reads, and
how the result moves over three meshes.
Do not report a number whose run or mesh has not been checked.
```

## Current API defaults

Source amplitude defaults to `amplitude_kind="current"`; pass it explicitly
when adapting older examples (witness: `tests/unit/sources/test_source_amplitude_kind.py`).
`write_touchstone` uses standard Touchstone ordering
(witness: `tests/unit/api/test_touchstone_interop.py`).
Matrix products use `jax.lax.Precision.HIGHEST`
(witness: `tests/contracts/test_matmul_precision.py`).
Boundaries per face: `BoundarySpec` and `Boundary` from `rfx.boundaries.spec`,
passed as `Simulation(boundary=...)`.
