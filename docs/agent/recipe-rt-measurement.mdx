Use this recipe when you need broadband power R(f) / T(f) spectra of a slab,
thin-film stack, periodic surface, or other scatterer. For guided-mode
S-parameters in a bounded waveguide, see [the sources and ports guide](/rfx/model/ports/)
instead.

## When to use

- Broadband reflectance and transmittance vs frequency for free-space or
  periodic-boundary geometries.
- Dispersive materials (Lorentz resonances, Drude metals) where frequency
  dependence is essential.
- Any case where the analytic transfer-matrix or Fresnel stack result is
  the benchmark.

**Not for**: guided modes, coaxial lines, microstrip — those have dedicated port
primitives and compute paths.

## Right primitives

### `add_flux_monitor`

On-the-fly DFT accumulation of the Poynting flux on a plane. Each frequency
component is integrated continuously throughout the run, so no time-series
storage is needed and no post-run FFT is required.

```python
sim.add_flux_monitor(axis="x", coordinate=refl_x, freqs=freqs_rt, name="refl")
sim.add_flux_monitor(axis="x", coordinate=trans_x, freqs=freqs_rt, name="trans")
```

### `run(n_steps=...)` and a probe on each plane

Both runs use one fixed record, `n_steps`, and put a probe on each flux plane.
From those probes rfx forms the ring-down witness (detail (e)), which says
whether the record held the whole response. If it does not pass, lengthen
`n_steps` for both runs. Detail (b) says what `run(until_decay=...)` does on these runs.

### Two-run reference subtraction

Run once without the scatterer (reference run) and once with it (sample run).
Subtract the DFT accumulators at the field level before computing the power flux.

## Two-run template

This template requires values supplied by the caller: `freq_max`, the domain
(`dom_x`, `dom_y`, `dx`), the slab corners (`slab_x_lo`, `slab_x_hi`) and
material (`eps_inf`, a Lorentz `pole`), the source (`f0`, `bw`), the monitor
planes (`refl_x`, `trans_x`, `freqs_rt`), the probes' `y_center` and the record
length `n_steps`; the complete
`examples/tutorials/slab_rt_flux_monitor.py` is the runnable reference. The
tutorial uses a lossless, dispersionless slab (εr = 4, no pole) and a fixed
1200-step record.

```python
import numpy as np
from rfx import Simulation, Box
from rfx.probes.probes import flux_spectrum, subtract_flux_monitors

def build_sim(with_slab: bool) -> Simulation:
    sim = Simulation(
        freq_max=freq_max, domain=(dom_x, dom_y, dx), dx=dx,
        boundary="cpml", cpml_layers=20, mode="2d_tmz",
    )
    if with_slab:
        sim.add_material("slab", eps_r=eps_inf, lorentz_poles=[pole])
        # Box must span full y/z extent including CPML padding —
        # with TFSF, transverse axes are periodic, and any cell
        # outside the material mask breaks the plane-wave assumption.
        sim.add(Box((slab_x_lo, -1, -1), (slab_x_hi, 1, 1)), material="slab")
    sim.add_tfsf_source(f0=f0, bandwidth=bw, polarization="ez", direction="+x")
    sim.add_flux_monitor(axis="x", coordinate=refl_x, freqs=freqs_rt, name="refl")
    sim.add_flux_monitor(axis="x", coordinate=trans_x, freqs=freqs_rt, name="trans")
    sim.add_vector_probe((refl_x, y_center, 0))
    sim.add_vector_probe((trans_x, y_center, 0))
    return sim

# Run 1 — reference (no scatterer)
sim_ref = build_sim(with_slab=False)
res_ref = sim_ref.run(n_steps=n_steps)
ref_refl_fm = res_ref.flux_monitors["refl"]
ref_trans_flux = np.asarray(flux_spectrum(res_ref.flux_monitors["trans"]))

# Run 2 — sample (with scatterer)
sim_slab = build_sim(with_slab=True)
res_slab = sim_slab.run(n_steps=n_steps)
slab_refl_fm = res_slab.flux_monitors["refl"]
slab_trans_flux = np.asarray(flux_spectrum(res_slab.flux_monitors["trans"]))

# Both records must hold the whole response (detail (e)); if not, lengthen n_steps for both runs
for res in (res_ref, res_slab):
    assert res.settling_witness["status"] == "pass", res.settling_witness["reason"]

# Field-level subtraction for reflection
scat_refl_fm = subtract_flux_monitors(slab_refl_fm, ref_refl_fm)
scat_refl_flux = np.asarray(flux_spectrum(scat_refl_fm))

# Reflection and transmission coefficients
T = slab_trans_flux / ref_trans_flux      # transmittance
R = -scat_refl_flux / ref_trans_flux      # reflectance (sign: reflection is −x)
```

## Critical details

### (a) Field-level subtraction is required

Poynting flux is bilinear in E and H. If you subtract the pre-computed flux
values (`F_slab - F_ref`), the cross terms do not cancel, and the result is
wrong for all scatterers. Subtracting the E and H DFT accumulators first, then
calling `flux_spectrum`, is exact because Maxwell's equations are linear.

`subtract_flux_monitors(sample, ref)` does exactly that, so nobody has to write
out the four private accumulator field names — and it raises `ValueError`
instead of broadcasting when the two monitors differ in plane, frequencies,
record length (`total_steps`) or DFT window.

### (b) Record length: one fixed record, checked by the witness

A flux spectrum is a DFT over the record, so a record that ends while the field
still rings leaves part of the response out of every bin. The template uses one
fixed `n_steps` for both runs and asserts the ring-down witness of detail (e),
which judges that per frequency bin. The tutorial's 1200-step record passes it
at about −139 dB for the reference run and −92 dB for the slab run.

`run(until_decay=1e-5)` also gave a passing witness on both runs, measured on
the tutorial's slab and on a Lorentz slab (8 mm, εr∞ = 2, one pole at 10 GHz).
Three things differ from a fixed record:

- In both measured cases the vacuum reference run did not reach the requested
  1e-5: its field energy stopped falling at 1e-13 to 3e-13 of the drive's peak
  energy, and the run ended on the float32 floor with an `AccuracyWarning`.
- On the tutorial's slab that reference run lasted 25,900 steps, about 22 times
  the 1200-step record, and R and T came out the same as the tutorial's to three
  decimals (the template's 20 CPML layers against the tutorial's 10).
- Under `until_decay` the `n_steps` argument is ignored; the run stops at the
  latest at `decay_max_steps`.

### (c) TFSF transverse-periodicity gotcha

`add_tfsf_source` forces the transverse axes (y, z) to be periodic. The
material `Box` must span the full y/z extent including the CPML padding. Any
cell outside the material mask breaks the plane-wave assumption. Use oversized
corners: `Box((x_lo, -1, -1), (x_hi, 1, 1))`.

### (d) Draw the slab at its corners, on the lattice

A dielectric `Box` is sampled at NODE coordinates, half-open `[lo, hi)`: a
slab drawn `lo = i*dx` to `hi = k*dx` owns nodes `i .. k-1` and realizes
exactly `hi - lo`. No nudge is needed or wanted.

What DOES bite is the float route to the corner. `center + d/2` can land one
ulp above the node that `hi` is meant to be, the half-open test then keeps
that node, and the slab realizes one cell too many against a closed form
evaluated at `d`. Spell on-lattice corners in lattice arithmetic —
`i_lo = round((center - d/2)/dx)`, `x_lo = i_lo*dx`,
`x_hi = (i_lo + round(d/dx))*dx` — and assert the realized extent from
`sim.fidelity_report()` before quoting anything against the Fresnel closed form.
`examples/tutorials/slab_rt_flux_monitor.py` does both.

### (e) Put a probe on each flux plane

A flux monitor keeps only its running DFT, so the monitor alone cannot show
whether the record held the whole response. The coverage line the tutorial
prints for each monitor is a geometric bound: the step by which the drive has
ended and a wave at the speed of light from the farthest corner of the TF/SF
box could have reached the plane. It counts neither repeated reflections nor
slower travel inside the scatterer, so it does not show that the response has
died away.

A probe records the fields at one point. rfx forms the ring-down witness
(`result.settling_witness`, `result.settling_db`) from the probes the run
declares, wherever they sit, and reports the worst. It leaves out records at
rounding level and, when at least one probe sits off every drive cell, the
probes that share a cell with a point source, a lumped or wire port or a
microstrip feed. The witness gives, for each frequency bin, the
share that a tail beyond the record would still add. It passes at a share of
1e-2 (−40 dB). A probe on each flux plane is what makes the witness speak for
the R/T read; a probe placed elsewhere for another purpose also enters the
verdict. For a laterally uniform slab or stack under normal incidence the
fields are the same across the plane, so one point per plane is enough. For a
periodic surface or another scatterer they vary across the plane, and one point
can sit where a still-ringing field is zero; use several points on each plane.

Without a probe, and with both monitors covered, the witness is `absent` and
every run warns `no ring-down settling witness ... flux monitors`; a monitor
the record does not cover turns it `undetermined`.

The tutorial puts an `add_vector_probe` on each plane. It records every
component at that point; in 2-D TMz the witness skips the components that stay
at zero or at rounding level, judged against the largest record of the same
kind (E or H) in the same cell, and judges Ez and Hy. Point probes on Ez and Hy
give the same witness values. At the tutorial's fixed 1200-step record the
witness reads about −139 dB for the reference run and −92 dB for the slab run,
and the script stops if either run does not pass.

The probe serves the witness only; R and T still come from the flux monitors
(see "Do NOT use" below).

## Do NOT use

**`add_probe` (time-series) + `np.fft.rfft`** for dispersive media.

A chirped pulse transmitted through a dispersive slab has frequencies arriving
at different times. A tapered time-gate window (Hann, Tukey), or a record that
ends before the chirped transmitted pulse has, introduces a frequency-dependent
bias because the chirped transmitted pulse and the incident reference pulse
have different effective envelopes under the same window.

`add_flux_monitor` applies no taper by default (`dft_window="rect"`): each
frequency is a DFT over the whole record, and the ring-down witness from a
probe on the plane (detail (e)) says whether the signal had ended before the
record did.

For dispersionless media there is no group-velocity chirp, so the raw
time-series approach does not produce this artifact — but `add_flux_monitor`
is still preferred for its cleaner interface.

## Known accuracy

The cross-validation case that gated normal-incidence slab R(f) and T(f)
against the analytic Fresnel / transfer-matrix result was removed on
2026-09-21. The analytic slab comparisons that remain are in
`tests/oracle/`; the tutorial's contract test
(`tests/contracts/test_tutorial_examples.py`) also bounds the tutorial's
band-mean deviations from the Fresnel curve at 0.02, a band mean in the sense
of the next paragraph.

Do not read a band-mean threshold as an accuracy statement about the fringe
structure: a band mean over an interference pattern is blind to every zero-mean
shape error, and with mean gates alone that case passed while the true slab
permittivity was 12.33% away from what the FDTD built (issue #812). If you need
an accuracy figure for a slab, quote per-fringe deviations, not band means.

For dispersive media, `tests/oracle/test_dispersive_fresnel_validation.py`
checks R(f) of a single Debye, Lorentz and Drude slab against the
transfer-matrix result. Its gate is the band mean of |R_fdtd − R_analytic|
(below 0.05; 0.01 for Drude), so it does not bound the fringe shape (above),
and T(f) has no closed-form check. Two source-verifiable facts to
keep in mind when comparing against other solvers: rfx discretizes
Lorentz and Drude poles with a second-order ADE (central difference,
Crank-Nicolson damping; `rfx/materials/lorentz.py`) and Debye poles with a
first-order Crank-Nicolson ADE (`rfx/materials/debye.py`), while some other FDTD solvers use
recursive-convolution D-field updates; both are O(Δt²) but produce slightly
different effective ε(f) near stiff resonances, so a small residual between
solvers at a sharp Lorentz peak is a discretization-level difference, not
necessarily a usage error in either tool.

## Canonical examples

- `examples/tutorials/slab_rt_flux_monitor.py` — **the recommended path**: `add_flux_monitor`
  + two-run field-level reference subtraction via the `Simulation` API, with a
  ring-down witness on both runs (detail (e)), an analytic Fresnel comparison and
  an energy-conservation readout. For its lossless slab R+T prints 1.000 at every
  frequency on the coarse demo grid; that follows from energy conservation in a
  lossless slab, not from accuracy, so it is not an accuracy check. With a lossy pole R+T falls
  below 1 by the absorbed share. Start here.
