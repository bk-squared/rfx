This page orients AI agents working from a fresh public clone of rfx. Read it
before writing any new simulation code.

## How this repo is organized

| Path | Contents |
|------|----------|
| `rfx/api/__init__.py` | `Simulation` class and all `add_*` builder methods |
| `rfx/api/_spec.py` | Module-level data structures: `Result`, `MaterialSpec`, `*SMatrixResult`, `MATERIAL_LIBRARY`, internal `_*Entry` bookkeeping classes |
| `rfx/sources/` | Source and port implementations (waveguide, TFSF, MSL, coaxial, lumped, Floquet) |
| `rfx/probes/` | Probe and monitor implementations (point probes, DFT-plane, flux monitors, NTFF) |
| `rfx/materials/` | Material helpers including Debye, Lorentz, and nonlinear dispersion models |
| `rfx/boundaries/` | Boundary condition implementations (CPML, UPML, PEC, PMC, Floquet/Bloch) |
| `rfx/sources/`, `rfx/api/_sparams.py` | Port implementations and S-parameter extraction (production lumped/wire driver: `rfx/probes/sparam_driver.py`) |
| `rfx/observables.py` | Differentiable accessor/objective factories on registered DFT-plane probes (`dft_field`, `field_energy`, `field_softmax`) — same factory style as `rfx/optimize_objectives.py` — plus `jacobian_fwd`, a batched forward-mode Jacobian wrapper for any `sim_fn(params) -> value` |
| `tests/` | Canonical usage examples for every API surface — start here |
| `validation/crossval/` | Claims-bearing cases and deliberate diagnostic reporters — roles are pinned in `validation/crossval/manifest.json`; check it before citing any script as validation |

## Hard rule for AI agents

Before writing a raw Yee loop (`update_h` / `update_e`) or an
FFT-of-probe-time-series analysis, run:

```bash
grep "def add_" rfx/api/__init__.py
```

and ask: **why can't the `Simulation` API do this?**

All `add_*` builder methods live in `rfx/api/__init__.py`. Module-level data
structures live in `rfx/api/_spec.py`. Grep `rfx/api/` recursively to cover
both. If the existing API handles your task, use it — do not re-implement at the
Yee-field level.

Run these commands from the repo root before writing new code in each area. Each
command is verified to return at least one hit on the current tree.

## Current port-family caveat

For coaxial one-port workflows, use `Simulation.compute_coaxial_line_reflection(...)`
inside its documented one-port transmission-line envelope. For coaxial 2-port
workflows, `Simulation.compute_coaxial_two_port(...)` (issue #489 stage 2) is
**VALIDATED WITH SCOPE** (PI decision 2026-08-06): an external openEMS referee
(crossval 21) brackets its own `|S21|` and, via the port's own measured `beta`,
phase on the through-line class; a mesh-refinement convergence witness
(`p ~= 1.5`) and a `GRAD_SAFE` `eps_scale` AD gate close the remaining legs. It
does NOT cover transitions to other port families: every DUT it can currently
gate against is still azimuthally symmetric (TM0n only) (see its docstring /
`CoaxialTwoPortResult` for the full evidence chain and scope statement). The
older `Simulation.compute_coaxial_s_matrix(...)` path remains
deprecated/experimental and must not be presented as the promoted coaxial claims
surface. For a coax<->microstrip transition, `Simulation.compute_coax_msl_transition(...)`
(issue #489 leg 4) exists but is **EXPERIMENTAL, DIAGNOSTIC-ONLY**: two committed fixtures
(attempt 1, then a longer-MSL-ladder attempt 2 per R2's escape clause), plus a settled
VESSL run (`369367252283`, `n_steps=135000`, 2026-08-06) of attempt 2's own fixture that
clears the -40 dB ring-down rule for the first time on this lane. gamma-vs-beta is now
**CONFIRMED** (a third checkpoint, at full settling, still in-band `[0.8,1.3]`). Passivity
is **ATTRIBUTED**: the settled max`|S|` is `0.9933` with the guard clean — the earlier
sub-settled excursions above 1 are now understood as truncation artifacts, not a real
violation. Reciprocity is now **MEASURED**, not merely disclosed — worst deviation `91.4%`
at full settling, explained by none of this lane's three retracted attributions and
deliberately NOT adjudicated between a genuine physical asymmetry and a surviving
extraction-instrument limitation. The MSL-driven column-power open question is
correspondingly SHARPENED (~99% of incident power unaccounted for at 6/8 GHz, only ~20% at
10 GHz), with a named but not-yet-run discriminating check (a closed-box, PEC-wall variant
of the fixture) as the next step (see
`docs/guides/sparameter_support_matrix.md`'s "Coax<->MSL transition" section and
`tests/test_coax_msl_transition.py`) — still do not cite it as a validated transition
result.

## What NOT to do

**Never** use time-series + FFT of probe data to compute `R(f)` or `T(f)` for
dispersive slabs. Time-window truncation produces artifacts that make the result
unreliable.

Use `add_flux_monitor` + two-run reference subtraction instead. The canonical
demonstration is `validation/crossval/03_straight_waveguide_flux.py`, which shows
the two-monitor flux pattern explicitly. For the reference-subtraction contract,
see the `add_flux_monitor` docstring in `rfx/api/__init__.py`.
