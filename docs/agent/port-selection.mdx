Use this page as the decision layer before choosing a primitive. The full primitive reference lives in the [sources and ports guide](/rfx/model/ports/); this page adds the device-class decision layer on top of it.

For evidence status and normative envelopes, the [S-parameter section of the support matrix](../guides/support_matrix.md#s-parameters) is the support contract; this guide does not supersede it.

## Selection Table

| Device class | Primitive | Compute path | Status | Hard limit / envelope |
|---|---|---|---|---|
| Rectangular waveguide | `add_waveguide_port` | `compute_waveguide_s_matrix` | E5-narrow (current port) | Multi-port S-matrix; requires at least two waveguide ports. Single-mode; validated empty-guide, PEC-short, slab analytic + external references including Meep/OpenEMS/Palace. Chain closure (theta to S to objective) is **chain-closed (v1.8)** for the uniform single-mode guide on the `normalize=False` and `normalize="flux"` lanes, after three pre-declared WR-90 runs of the chain battery — with contract criterion 1 (forward identity: the reverse-mode-traced result equals the untraced one) and 3(a) (AD-vs-FD) read with JAX 64-bit mode enabled on the flux lane, the forward default still float32. A float32 gradient pipeline on the flux lane, junctions, multimode and nonuniform meshes are outside that declaration; "chain-closed" is not "supported". See the waveguide row of the [support matrix](../guides/support_matrix.md) for the numbers and fences before relying on this path for a differentiable chain. |
| Microstrip / MSL | `add_msl_port` | `compute_msl_s_matrix` | E5-narrow / eigenmode-blocked | Use only within the characterized-not-tight MSL envelope in the [support contract](../guides/support_matrix.md#s-parameters). The MSL open-stub notch filter is compared with frozen external solver data by `tests/crossval/msl_notch_filter/test_msl_notch_filter.py`; the retired script's committed run logs and the numbers quoted from them left with it on 2026-09-22. Eigenmode is unsupported (fenced); the non-uniform graded-mesh lane runs via the laplace feed (internally gated, external validation still owed). |
| Coaxial (promoted path) | `add_coaxial_port` | `compute_coaxial_line_reflection` | **broad_e5_passed** | One-port transmission-line reflection path (forward AND `jax.grad` optimization via `eps_scale`). Broad-E5 physics (analytic Γ envelope over short/open/matched and resistive loads 25 Ω / 100 Ω, two characteristic impedances, mesh-resolution sweep; `max \|Γ\|` dev 0.037 ≤ 0.05) + independent Meep broad-E4 cross-check 4–12 GHz, both committed under `tests/fixtures/`, + end-to-end differentiable (composition AD-vs-FD gate). Clean-checkout auditor returns `coaxial_port` PASSED. |
| Lumped / RLC excitation | `add_lumped_rlc` / `add_port` | `Simulation.run(compute_s_params=True, ...)` or `Simulation.forward(port_s11_freqs=...)` | E2/E3 partial (lumped), E0/E1 (forward S11) | Lumped-port envelope for V/I extraction. Nonuniform lumped-port S-parameter extraction is not within the current validated envelope. `compute_s_params` path is only for `add_port` simulations. |
| Free-space scattering | `add_tfsf_source` | Field, flux, or NTFF observables (where separately supported) | Not a port | Plane-wave total-field/scattered-field drive. Not a port calibration path; no promoted S-parameter compute path. |
| Periodic surfaces | `add_floquet_port` | No promoted API | E2/E3-modal/slab-analytic; no promoted S-matrix API | Experimental Floquet/Bloch excitation. | Antennas / radiation | `add_source` / `add_polarized_source` + `add_ntff_box` | Near-to-far-field post-processing | Supported (NTFF separately validated) | Use source primitives for drive; use `add_ntff_box` for radiation observables (directivity, RCS, far-field patterns). Do not route radiation results into port S-parameters without a supported extraction row. |

## Decision Tree

1. **Rectangular waveguide** → `add_waveguide_port` + `compute_waveguide_s_matrix`. Needs two or more ports for a full S-matrix.
2. **Microstrip / MSL guided line** → `add_msl_port` + `compute_msl_s_matrix`. Use the default `mode="laplace"` feed (works on uniform and non-uniform meshes; the non-uniform lane is internally gated, externally unvalidated). `mode="eigenmode"` is unsupported (fenced).
3. **Coaxial** → `add_coaxial_port` in experimental uniform single-device `run()` / `forward()` for a device feed. The line-reflection and two-port calculators remain available for their documented line families.
4. **Lumped component or discrete terminal** → `add_lumped_rlc` or `add_port`. Keep results within the lumped-port interpretation; this is not a waveguide or coaxial S-matrix path.
5. **Free-space incident field** → `add_tfsf_source`. No port calibration applies.
6. **Periodic structure requiring modal excitation** → `add_floquet_port` only within the E2/E3 analytic-slab envelope. No promoted S-matrix API.
7. **Antenna or radiation observable** → `add_source` or `add_polarized_source` plus `add_ntff_box`.

## Coaxial Compute Path Caveat

`add_coaxial_port(...)` builds a coax line, matched feed, TEM drive and voltage planes in experimental uniform single-device `run()` and `forward()`. `position` is the reference plane; `face="top"` or `"bottom"` selects the feed side and `pin_length` extends the pin toward the device. `run(compute_s_params=True, s_param_freqs=...)` and `forward(port_s11_freqs=...)` read S11 at that plane using the built line impedance, then renormalize it to `impedance`. The radii, `pin_length` and `impedance` are static declarations; PEC occupancy elsewhere can be differentiated. The coaxial calculators remain available with their own line layouts and limits.

Uniform mesh, one device, one coax port and no other S-port family; face top or bottom, float32, three-dimensional second-order Yee, CPML on all six faces, no periodic axis or TF/SF. The shell needs at least one whole cell from every lateral absorber, enough axial room for the line, and an NTFF box, when declared, containing the whole port. No conformal PEC, subpixel smoothing, eps_override or sigma_override.

Experimental uniform coax ports: same-line calculator equality, run()/forward() equality, bottom-feed, NTFF-leakage and occupancy-gradient checks define the validation scope; the antenna-level result against an independent solver is not yet shown.

`compute_coaxial_line_reflection` is the coaxial transmission-line reflection path and is `broad_e5_passed`: broad-E5 physics (analytic Γ envelope) + independent Meep broad-E4 short/open, both with committed evidence (`tests/fixtures/coax_broad_e5/`, `tests/fixtures/coax_broad_e4/`), plus an end-to-end differentiable path (`grad(S11)` w.r.t. the dielectric via `eps_scale`; composition AD-vs-FD gate `tests/unit/autodiff/test_coax_end_to_end_ad.py`). The clean-checkout auditor returns `coaxial_port` PASSED. The [support matrix](../guides/support_matrix.md#s-parameters) coaxial rows document the current lanes.

## Compute-Path/Port Pairing Rules

Keep these pairings exact. Most mispairings raise a `ValueError`; treat any combination that does not raise as undefined rather than validated.

- `compute_waveguide_s_matrix` → only for `add_waveguide_port` simulations
- `compute_msl_s_matrix` → only for `add_msl_port` simulations
- `compute_coaxial_line_reflection` → only for the documented one-port coaxial envelope
- `run(compute_s_params=True, ...)` → only for `add_port` lumped/wire ports
- `forward(port_s11_freqs=...)` → only for `add_port` lumped/wire ports

## When No Port Family Fits

Stop before improvising. If no row in the [S-parameter section of the support matrix](../guides/support_matrix.md#s-parameters) covers the geometry, boundary conditions, source normalization, and observable you need:

1. Check the full [support matrix](../guides/support_matrix.md#s-parameters) and [support matrix JSON](../guides/sparameter_support_matrix.json) for any partial or experimental row that covers part of the envelope.
2. Check [docs/guides/](../guides/) for evidence rules and methodology notes.
3. Do not invent a new extraction scheme and label it validated. Add an explicit evidence row first.
4. If the structure is close to a supported family (e.g., a variant waveguide geometry), confirm it is within the documented envelope before claiming the family's status.

An unverified extraction that reports plausible-looking numbers is not a validated result.

## When a Gate Fails

Do not redesign extractors from the failure symptom alone — the common
obvious-looking fixes in this area are already falsified. Walk the
[failed-gate triage recipe](./recipe-failed-gate-triage) first.

`compute_far_field` is jittable; this does not establish support for an
NTFF adjoint objective (witness: `tests/unit/autodiff/test_forward_jit_contract.py`).
