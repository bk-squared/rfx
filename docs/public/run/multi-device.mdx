## What it is for

A model too large for one GPU, or too slow on one, can be split over several
devices. rfx cuts the domain into slabs along x, gives each device one slab,
and exchanges the fields on the faces between slabs after every time step. The
result should be the same physics as on one device, to within rounding. This
page is how to ask for it, what a multi-device run carries today, and what it
refuses.

## How to use it

`run(devices=[...])` takes a list of JAX devices. With two or more it splits
the model; with `None` or one device it runs normally. On a machine without
several GPUs you can try it on CPU by asking XLA for several host devices
before JAX is imported:

```python
import os
os.environ.setdefault("XLA_FLAGS", "--xla_force_host_platform_device_count=2")

import jax
import numpy as np
from rfx import Box, GaussianPulse, Simulation


def build():
    sim = Simulation(freq_max=4e9, domain=(0.06, 0.05, 0.04), dx=2e-3,
                     boundary="cpml", cpml_layers=8)
    sim.add_material("slab", eps_r=4.0, sigma=0.01)
    sim.add(Box((0.024, 0.019, 0.014), (0.036, 0.031, 0.026)), material="slab")
    sim.add_port((0.018, 0.025, 0.020), "ez", impedance=50.0,
                 waveform=GaussianPulse(f0=3e9, bandwidth=0.8))
    sim.add_probe((0.044, 0.025, 0.020), "ez")
    return sim


one = build().run(n_steps=300, skip_preflight=True)
two = build().run(n_steps=300, skip_preflight=True, devices=jax.devices()[:2])
a, b = np.asarray(one.time_series), np.asarray(two.time_series)
print(len(jax.devices()), float(np.max(np.abs(a - b)) / np.max(np.abs(a))))
s1, s2 = np.asarray(one.s_params), np.asarray(two.s_params)
print(s1.shape, float(np.max(np.abs(s1 - s2))))
```

```text
2 7.906159225967713e-06
(1, 1, 50) 1.3011879218538525e-07
```

Split over two devices, the probe signal differs from the one-device run by
8×10⁻⁶ of its peak and S11 by 1.3×10⁻⁷: float32 rounding, not a different
model.

What to know:

- **Uniform mesh:** `run(devices=...)`. **Graded mesh:** `run(devices=...)`
  too, or `forward(distributed=True, devices=...)` for gradients; with
  `distributed=True` and no `devices`, all visible devices are used, and at
  least two are required. `forward(distributed=True)` on a uniform mesh is
  refused.
- `forward(distributed=True)` returns the probe signals and their gradients
  with respect to the material overrides; it returns no S-parameters or far
  field.
- `exchange_interval` must be 1 (the default): the slabs exchange fields every
  step.
- Splitting is along x only. A domain whose x size does not divide evenly is
  padded.

### The outer-jit rule

On GPUs, do not wrap a multi-device call in your own `jax.jit` (or `lax.scan`,
`jax.checkpoint`). The runner compiles its own time loop; an enclosing compile
makes XLA encode each device's position in a way CUDA graphs reject. rfx
refuses that call with a message that gives both ways out: call
`run(devices=...)` / `forward(distributed=True)`, and `jax.grad` of it, without
`jax.jit`; or start the process with `XLA_FLAGS=--xla_gpu_enable_command_buffer=`
set before JAX is imported. On CPU the rule does not apply.

## What is checked

Tests compare multi-device runs with one-device runs of the same model:

- the drive of field and current sources at slab seams and inside slabs, over
  two and three devices: field sources bit-identical, current sources within
  9 float32 rounding steps (`tests/unit/runners/test_distributed_drive_table.py`);
- lumped-port S over every entry and frequency within 9×10⁻⁶
  (`tests/unit/runners/test_distributed_lumped_port_s.py`);
- the far field with seams, padding, a dielectric and absorbers within 5×10⁻⁵
  (`tests/unit/runners/test_distributed_ntff.py`).

Every input a multi-device path does not implement is refused before the first
step, or handed to a one-device run with a warning (below).

## What is refused, and the way through

A few inputs make the run fall back to one device, with the warning "Falling
back to single-device execution with the same arguments": a plane wave or a
waveguide port on a uniform mesh, and a waveguide port on a graded mesh. The
result is the one you asked for, on one device.

These are refused:

| Input | Path | Instead |
|---|---|---|
| a PMC face, a periodic axis, a Floquet port | all multi-device | one device |
| a microstrip or coaxial port, a lumped RLC element, a passive port | all multi-device | one device |
| a lumped or wire port with an impedance | graded mesh (`run()` and `forward()`) | a uniform mesh |
| a wire port with `reference_plane_cells` or an explicit radius | uniform mesh | one device |
| a plane wave | graded mesh | a uniform mesh, or one device |
| a Kerr material, a surface-impedance sheet, `add_refinement` | all multi-device | one device |
| `precision` other than float32, `stencil_order=4`, UPML | all multi-device | float32, second order, CPML |
| a DFT plane, a flux monitor | all multi-device | one device |
| a far-field box | graded mesh | a uniform mesh |
| `until_decay`, `snapshot`, `checkpoint`, `subpixel_smoothing`, `conformal_pec`, `ringdown` | `run()` | a fixed `n_steps`, one device for the rest |
| `exchange_interval` other than 1 | all multi-device | 1 |
| a graded mesh with neighbouring cells more than 5:1 apart | graded mesh | a gentler grading |
| an outer `jax.jit` on GPUs with command buffers on | all multi-device | see the outer-jit rule |

## Accuracy

A multi-device run is the one-device model to within the rounding bars above.
Its accuracy is that of the one-device run.
