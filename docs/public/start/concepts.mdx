rfx is a finite-difference time-domain (FDTD) solver. It divides space into
small rectangular cells, steps Maxwell's equations forward in time, and records
what you ask for. This page explains the choices a model makes and what each
one does to your result. Read it once before you build your own device.

## The grid and the time step

rfx uses the standard **Yee lattice**. Each field component lives at its own
position in the cell. E components sit on cell edges and H components sit on
cell faces. You rarely need the exact positions, but they explain two things
you will see:

- Geometry snaps to the lattice. A dielectric or metal-volume face drawn
  between two grid planes lands on the nearest plane, and a metal sheet lands
  on the nearest node plane. A sheet's in-plane edge follows its own rule,
  given under [Three kinds of conductor](#three-kinds-of-conductor).
  `sim.fidelity_report()` prints the declared and realized position of every
  face.
- A probe or port reads a field at a grid location. The coordinate snaps to
  the nearest grid node, up to half a cell away on each axis, and a probe's
  field component sits a further half cell from that node on the Yee grid.

**Cell size.** The cell must resolve the shortest wavelength *inside the
material*, λ_eff = c / (f_max √ε_r). Aim for at least 15–20 cells per λ_eff for
propagation, and more for anything phase-sensitive. Preflight warns when a
dielectric has fewer than 15, or fewer than 20 when the model has waveguide
ports or flux monitors. The thinnest feature that matters also needs a
few cells, such as a substrate or a gap. On a uniform grid, those two
requirements together set `dx`. When they conflict, use a graded mesh; see
[Non-Uniform Mesh](/rfx/model/domain-mesh/).

**Time step.** rfx picks the largest stable step from the cell size (the
Courant limit). You normally leave `dt` alone. A run of N steps covers
`N * result.dt` seconds.

**Cost.** Memory and time per step scale with the number of cells. Halving
`dx` in 3-D gives 8× the cells and about 2× the steps, so roughly 16× the
work. Start coarse, then refine.

## Boundaries

The boundary decides what happens at the edge of the domain.

| Boundary | Use it for | Notes |
|---|---|---|
| `"cpml"` | open problems: antennas, scattering, lines that leave the box | an absorber `cpml_layers` cells thick (default 16), added **outside** `domain`. A structure drawn to the face continues through the absorber, and the cells next to the face should stay uniform over that depth |
| `"pec"` | closed problems: cavities, shielded boxes | energy cannot leave, so resonances ring indefinitely |
| `"pmc"` (via `BoundarySpec`) | a symmetry plane, which halves the problem | only where the fields really are symmetric |
| `"periodic"` (via `BoundarySpec`) | infinite arrays and unit cells | the paired faces go together |
| `"upml"` | legacy absorber | reflects noticeably more than CPML; prefer CPML |

A single string (`"cpml"`, `"pec"` or `"upml"`) applies to all six faces. To
set each face separately, or to use `"pmc"` or `"periodic"`, pass a
`BoundarySpec`. A dict per axis, such as
`{"x": "cpml", "y": "pec", "z": "pec"}`, also works:

```python
from rfx import Simulation
from rfx.boundaries.spec import Boundary, BoundarySpec

# Open on all sides except an infinite PEC ground at z = 0.
spec = BoundarySpec(x="cpml", y="cpml", z=Boundary(lo="pec", hi="cpml"))
sim = Simulation(freq_max=10e9, domain=(0.02, 0.02, 0.01), dx=0.5e-3,
                 boundary=spec, cpml_layers=8)
print(spec.to_dict())
```

The PEC face in this example is an infinite ground under an open problem. A
closed metal box with one absorbing wall is a different thing: it is neither a
closed resonator nor an open radiator, and its Q means nothing. A PEC **boundary** is also infinite in its
own plane. For a finite ground plane, draw a metal sheet inside an all-CPML
domain instead, as described under
[Three kinds of conductor](#three-kinds-of-conductor).

## Materials

A material has a relative permittivity `eps_r`, a conductivity `sigma` (S/m)
and optionally a permeability `mu_r`. Frequency-dependent materials use Debye
or Lorentz poles. rfx ships a small library that includes `"fr4"`,
`"rogers4350b"`, `"ptfe"`, `"copper"` and `"pec"`. See
[Materials and Geometry](/rfx/model/materials/).

Any material with `sigma >= 1e6` S/m is treated as a **perfect conductor**.
Its tangential E is forced to zero. The finite conductivity is not used, so
library `copper` behaves as lossless PEC. For conductor loss on a metal sheet,
use `add_thin_conductor(..., surface_impedance_f0=f0)`.

## Three kinds of conductor

Metal that rfx accepts inside the domain is exactly one of three things.
**Your declaration decides which**, not the shape's size on the mesh. A PEC
shape that fits none of them is refused (see below the figure):

| Kind | Real-world object | Declare it with | What the solver builds |
|---|---|---|---|
| **sheet** | etched copper: ground plane, patch, trace | `sim.add_thin_conductor(Box(...))` with zero thickness on one axis | one grid plane with in-plane E zeroed; occupies no cell |
| **volume** | plate, iris, post, machined wall | `sim.add(shape, material="pec")` | walls at both drawn faces, interior shorted |
| **wire** | thin filament | `PolylineWire(..., radius=0)`. A positive radius declares a volume instead, refused below half the smallest local cell | a path of zeroed E edges |

```python
from rfx import Box
from rfx.mesh_edges import edge_aware_profiles

substrate = Box((0.005, 0.005, 0.004), (0.015, 0.015, 0.005))
foil = Box((0.005, 0.005, 0.004), (0.015, 0.015, 0.004))   # zero thickness in z
block = Box((0.007, 0.007, 0.006), (0.009, 0.009, 0.007))

# x and y mesh lines placed 0.35 cell inside the foil's drawn edges.
profiles = edge_aware_profiles((0.02, 0.02, 0.01), 0.5e-3,
                               sheets=[foil], solids=[substrate, block])

sim = Simulation(freq_max=10e9, domain=(0.02, 0.02, 0.01), dx=0.5e-3,
                 boundary="cpml", cpml_layers=8, **profiles)
sim.add_material("substrate", eps_r=3.66)
sim.add(substrate, material="substrate")

# 35 um copper foil on the substrate floor: a sheet.
sim.add_thin_conductor(foil)

# A 2 x 2 x 1 mm metal block: a volume.
sim.add(block, material="pec")

sim.fidelity_report()   # declared vs realized planes for every entity
```

The first `add_thin_conductor` call warns that the sheet is lossless PEC. That
warning is expected: see the materials note above.

Preflight takes a sheet's free edge to lie 0.35 of a cell past its last mesh
node, so on a plain uniform grid it predicts this 10 mm foil wider than drawn.
Preflight reports a sheet predicted more than 1 % off its drawing as an error, so
`run()` and `forward()` stop before the first step. Build the in-plane mesh with
`rfx.mesh_edges.edge_aware_profiles`, as above: it puts the sheet's last nodes
0.35 cell inside its drawn edges. The offset was measured where the cell
normal to the sheet is as long as the in-plane cell beside its edge; here they
are 0.5 and 0.475 mm, a ratio of 1.05, and the foil lies on the substrate's
bottom face, where the offset at that ratio has not been measured. Or pass
`Simulation(..., snap="declared")` to accept the difference as a warning,
recorded in `sim.realized_geometry()`. With the graded in-plane mesh, preflight
also warns that the grading reaches the cells next to an absorbing face, which
should stay uniform over as many cells as the face has absorber layers.
`edge_aware_profiles` adjusts the cells all the way to the domain faces, so a
wider margin does not clear this warning, and its effect on the absorber has
not been measured (see
[Non-Uniform Mesh](/rfx/model/domain-mesh/#building-a-z-profile)).

A PEC shape that is thinner than one cell but not zero is neither a sheet nor a
resolved volume. Preflight reports it as an error and `run()` refuses it, so
you must choose one or the other. The full
rule, with the index conventions, is in
[How conductors land on the lattice](/rfx/model/conductors/#how-conductors-land-on-the-lattice).

## Sources and ports

- A **source** (`add_source`, `add_tfsf_source`, `add_polarized_source`)
  injects a field. It has no impedance and does not load the structure. Use it
  for fields, resonances, far-field patterns and scattering.
- A **port** injects a signal *and* terminates the line in a known impedance,
  so rfx can compute S-parameters. Each port family has its own S-parameter
  route, and only that route gives S-parameters for it:

| Structure | Port | S-parameter calculator |
|---|---|---|
| discrete feed, lumped component terminals | `add_port(...)` (lumped; `extent=` makes a wire port) | `run(compute_s_params=True)` or `forward(port_s11_freqs=...)` |
| microstrip line | `add_msl_port(...)` | `compute_msl_s_matrix()` |
| rectangular waveguide | `add_waveguide_port(...)` | `compute_waveguide_s_matrix()` |
| coaxial line | `add_coaxial_port(...)` | `compute_coaxial_line_reflection()`, `compute_coaxial_two_port()`; experimental: S11 from `run(compute_s_params=True)` or `forward(port_s11_freqs=...)` on a uniform mesh on one device |

Probes, flux monitors and DFT planes record fields. They do not define a
reference impedance or a reference plane, so they cannot produce S-parameters.
[Sources and Ports](/rfx/model/ports/) covers every family.

## Observables

| Want | Use |
|---|---|
| a field value over time at a point | `add_probe`, `add_vector_probe` |
| a field on a plane at chosen frequencies | `add_dft_plane_probe` |
| power through a plane (R, T, absorption) | `add_flux_monitor` |
| radiation pattern, directivity, RCS | `add_ntff_box`, then `compute_far_field`; for RCS, `compute_rcs`, a lower-level function that takes a uniform `rfx.Grid` and material arrays instead of a `Simulation` and runs its own plane-wave simulation ([Far Field and RCS](/rfx/measure/far-field-and-rcs/)) |
| resonant frequencies and Q | a probe plus `result.find_resonances()` (matrix pencil fit) |
| S-parameters | a port family and its calculator (table above) |

## Is the run finished?

A pulse must ring down before its spectrum means anything. Every spectral
quantity is a Fourier transform of a finite record: S-parameters, flux,
far fields, DFT planes and resonances. If the record stops while energy is
still bouncing around, the result is wrong in a way that no warning can fully
catch.

- Check `result.settling_witness["status"]`. rfx judges each port's record
  and each point probe, at every frequency the run's spectral results read.
  From the poles still ringing after the source ends it estimates how much of
  the value lies past the record's end; `settling_db` is the worst share in
  dB, and at or below −40 dB the status is `pass`. `fail`, `undetermined` and
  `absent` (nothing recorded to judge) are not passes. Flux, far fields and DFT
  planes are judged only through a probe: without one the status is `absent`,
  so add a point probe away from the source.
- The S-parameter calculators run one simulation per driven port, and warn
  when the record of any of them ends too early.
- High-Q structures need long records. A resonator with quality factor Q
  decays over roughly Q / (π f) seconds.

## Preflight and fidelity

Two checks run without a solve:

- `sim.preflight()` returns a report of errors and warnings about the setup.
  Examples are cell size against wavelength, structures touching the
  absorber, far-field boxes too close to the radiator, graded-mesh problems and
  lossless resonators. `run()` repeats it automatically.
- `sim.fidelity_report()` prints where each shape actually landed on the grid.

Neither check is an accuracy guarantee. A clean preflight means rfx found none
of the mistakes it knows about. Accuracy comes from a convergence study and a
comparison with a reference; see
[Is the mesh fine enough?](/rfx/check/mesh-convergence/) and
[Validation](/rfx/guide/validation/).

## `run()` versus `forward()`

- `sim.run(...)` is the general entry point. It returns a `Result` with probe
  time series, S-parameters, DFT planes, flux and far-field data.
- `sim.forward(...)` is the entry point built for gradients. Wrap it in
  `jax.grad` to get gradients with respect to material overrides or design
  variables. It supports a narrower set of features.
- `run()` also passes gradients on one device when a declared value, such as a
  material's `eps_r` or a source amplitude, is traced, but it takes no override
  or design argument. The comparison is in
  [run() and forward()](/rfx/run/run-and-forward/). See
  [Autodiff and Adjoint](/rfx/design/gradients/) and
  [Inverse Design](/rfx/design/optimization/).

## Precision

The default is `precision="float32"`, which suits most work and is what the
GPU runs fastest. `"float64"` needs JAX 64-bit mode: build and run the simulation
inside `with jax.enable_x64():`. `"mixed"` stores fields in float16. Float64 runs on one
device, on a uniform or graded mesh; mixed runs on a uniform mesh on one device. Mixed precision raises the CPML's reflection
floor, so avoid it for low-reflection or S-parameter work.
