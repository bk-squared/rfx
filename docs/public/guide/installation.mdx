## Basic install

```bash
pip install rfx-fdtd
```

`rfx` requires Python 3.10+ and installs JAX, NumPy, SciPy, matplotlib, and
h5py.

The package name on PyPI is `rfx-fdtd`, while the Python import remains:

```python
import rfx
```

For the packaged local Studio, background experiment CLI, and Model Context
Protocol (MCP) server, install the Studio extra:

```bash
pip install "rfx-fdtd[studio]"
rfx studio --workspace .rfx-studio
```

See [Studio, CLI, and MCP Experiments](/rfx/guide/studio-experiments/) for the
current UI scope, shared-workspace rules, replay, approvals, and remote
deployment requirements.

## Verify your install

After installing, confirm the environment can actually run a simulation.

First run the bundled diagnostics command:

```bash
rfx-diagnose
```

It prints a PASS / WARN / FAIL report (Python and rfx versions, the JAX
backend and devices, core dependencies, optional extras) and finishes with a
tiny end-to-end FDTD run. It exits `0` only when every critical check
passes; WARN lines (CPU-only backend, x64 disabled) are informational.

The diagnostic's final short run is the installed-package execution check.
Examples under `examples/` are available only from a source checkout; they are
not installed as wheel data.

## NVIDIA CUDA GPU support

```bash
pip install --upgrade "jax[cuda12]"
python -c "import jax; print(jax.devices())"
```

See the official JAX installation guide for CUDA/cuDNN details.

## Experimental Apple Metal research lane

This opt-in lane is for exploratory forward runs on an Apple-silicon
(`darwin`/`arm64`) Mac running macOS Sonoma 14.4 or newer. It is not the normal JAX GPU support path: the
[official JAX installation guide](https://docs.jax.dev/en/latest/installation.html#mac-gpu)
lists Mac GPU as unsupported and directs users to CPU. rfx therefore treats
Apple's [legacy experimental `jax-metal`
plug-in](https://developer.apple.com/metal/jax/) as research-only.

Install the Xcode command-line tools if the Mac does not already have them,
then create an isolated environment:

```bash
xcode-select --install
python3 -m venv .venv-metal
source .venv-metal/bin/activate
python -m pip install --upgrade pip wheel
python -m pip install "rfx-fdtd[metal]"
python -c "import jax; print(jax.__version__, jax.default_backend(), jax.devices())"
rfx-diagnose
```

The `metal` extra uses exact pins: `jax==0.4.34`, `jaxlib==0.4.34`, and
`jax-metal==0.1.1`. These legacy plug-in dependencies are deliberately absent
from the `all` extra so a development install cannot silently replace its JAX
stack.

The only Metal research scope is:

- a uniform Cartesian Yee grid;
- the second-order stencil, without refinement, conformal PEC, or subpixel
  smoothing;
- one local device and a forward-only time-domain run;
- real `float32` fields; and
- static isotropic materials, point sources, and basic time-domain field
  probes. A lumped `add_port()` is usable as a real time-domain excitation
  only with explicit `compute_s_params=False`.

Metal is unsupported for reverse-mode AD or optimization: the measured
reverse-mode path terminates the Python process with a native segmentation
fault. It is also unsupported for port spectra/S-parameters (including the
waveguide, MSL, and coaxial calculators), DFT/frequency-domain observables,
flux, NTFF/far-field, Floquet/Bloch, complex dtypes, `float64`, distributed
execution, batched/`vmap` sweeps, full-field snapshots, nonuniform or refined
meshes, fourth-order stencils, conformal PEC, subpixel/anisotropic materials,
Debye/Lorentz/Kerr materials, TFSF, periodic boundaries,
thin/surface-impedance conductors, lumped RLC, and ADI. Use CPU for all of those
workflows and reproduce a Metal observation there before making a scientific
claim.

To keep the Metal packages installed but force JAX back to its CPU backend:

```bash
JAX_PLATFORMS=cpu rfx-diagnose
JAX_PLATFORMS=cpu python your_script.py
```

In a source checkout, the opt-in hardware gate is:

```bash
python -m pytest -o addopts='' tests/test_metal_e2e.py
```

## Development install

```bash
git clone https://github.com/bk-squared/rfx.git
cd rfx
pip install -e ".[dev]"
python examples/quickstart/hello_world.py
```

The hello-world script builds a tiny box, injects one pulse, records one field
probe, and prints a short finite-data summary.

The `dev` extra includes:

- `pytest`
- `pytest-xdist`
- `ruff`

## System requirements

- Python: 3.10 / 3.11 / 3.12
- CPU: modern x86_64 or Apple silicon (`arm64`)
- Supported GPU acceleration: NVIDIA + CUDA 12+
- Experimental research GPU: Apple silicon Metal, within the forward-only
  `float32` scope above
- RAM: 4 GB minimum, 16 GB+ recommended for larger 3D runs

## Next steps

From a source checkout with the development install above, run
`examples/quickstart/hello_world.py`, then follow the ordered tutorials in
`examples/tutorials/`; `examples/README.md` lists the sequence. For a wheel-only
install, use `rfx-diagnose` as the execution check because the wheel does not
include `examples/`.
