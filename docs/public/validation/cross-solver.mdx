This page is about running a comparison yourself. The cases and what they show
are on [Benchmarks](/rfx/guide/benchmarks/).

## Run a comparison

The scripts are in `validation/crossval/` in a source checkout; they are not
installed with the wheel. Run one from the repository root:

```bash
python validation/crossval/15_patch_antenna_rt5880.py
```

By default it compares the committed rfx and reference results, which takes
seconds and needs no external solver. [Benchmarks](/rfx/guide/benchmarks/#reproduce)
shows how to re-solve either side.

The comparisons in `tests/crossval/` run through pytest. Most are long and
marked `gpu` or `slow`, which the default test selection skips, so clear the
default selection to run one (a GPU is recommended):

```bash
python -m pytest -o addopts="" tests/crossval/msl_notch_filter -q
```

## Read the result

| Exit code | Meaning |
|---|---|
| `0` | Every check passed, including the comparison with the reference. |
| `1` | A check failed. |
| `2` | The rfx checks passed, but the reference result or solver was missing. Inconclusive, not a pass. |

## Cite the result

A comparison holds for the geometry, mesh, band, source, port, materials,
boundaries and observable of that script. When you cite one, give the script
path, the commit, those settings, the reference and the thresholds it used.
Do not carry the result over to a different port, material model, boundary or
mesh without a comparison for that setup.
