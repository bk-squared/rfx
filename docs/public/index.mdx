rfx is a 3-D finite-difference time-domain (FDTD) electromagnetic simulator
for RF and microwave engineering. It is written in JAX, so it runs on a GPU and
can differentiate a simulation with respect to its inputs.

Use it to:

- simulate antennas, filters, transmission lines, waveguides, cavities and
  scatterers in the time domain;
- extract S-parameters, resonances and Q, radiation patterns, RCS, and power
  flow;
- compute gradients through the solver for sensitivity analysis and inverse
  design.

## Install

```bash
pip install rfx-fdtd                  # CPU
pip install "jax[cuda12]" rfx-fdtd    # NVIDIA GPU
```

## A first simulation

```python
from rfx import Box, GaussianPulse, Simulation

sim = Simulation(freq_max=5e9, domain=(0.06, 0.04, 0.04), dx=2e-3,
                 boundary="cpml", cpml_layers=8)
sim.add_material("slab", eps_r=3.0, sigma=0.005)
sim.add(Box((0.028, 0.0, 0.0), (0.036, 0.04, 0.04)), material="slab")
sim.add_source((0.014, 0.02, 0.02), "ez",
               waveform=GaussianPulse(f0=3e9, bandwidth=0.8),
               amplitude_kind="current")
sim.add_probe((0.046, 0.02, 0.02), "ez")

sim.preflight().raise_for_failure()
result = sim.run(n_steps=1000)
print(result.time_series.shape)
```

The [Quick Start](/rfx/guide/quickstart/) explains each line.

## What is well supported

rfx has many features, and they are not equally mature. The most-tested path is
the **uniform Cartesian Yee solver** on one device, with PEC or CPML
boundaries. On that path it offers:

- point sources, plane waves, probes, flux monitors, Harminv resonance
  extraction and near-to-far-field transforms;
- S-parameters from four port families: lumped/wire, microstrip, rectangular
  waveguide and coaxial. Each family has its own calculator and its own
  validated range.

Graded (non-uniform) meshes, the ADI solver, multi-device runs, subgridding and
Floquet ports exist with narrower or experimental support.
[Support Boundaries](/rfx/api/support-boundaries/) lists the status of each.
When rfx knows it cannot do what you asked, it raises an error instead of
returning a number. Some combinations outside the main path can still ignore a
setting without saying so. Those are tracked as
[open issues](https://github.com/bk-squared/rfx/issues), and the defects a user
can hit are listed on the
[known limitations](https://github.com/bk-squared/rfx/blob/main/docs/guides/known_limitations.md)
page. Stay on the well-supported path unless you have checked the status of the
feature you need.
