<section data-rfx="hero">
  <p>rfx is an open-source 3-D FDTD simulator for RF and microwave engineering, written in JAX. Write a loss on S-parameters, a radiation pattern or a field, and rfx returns its derivative with respect to the permittivity of every cell in a design region, from one forward and one reverse simulation. An optimiser can then shape a design cell by cell.</p>
  <p data-rfx="actions"><code>pip install "rfx-fdtd>=2.0.0rc1"</code> <a href="/rfx/showcase/">See the showcase →</a> <a href="https://github.com/bk-squared/rfx">GitHub</a></p>
</section>

A dipole above a 30 mm ground plate radiates a broad beam. In front of it sits a
90 × 90 × 30 mm block whose permittivity may take any value PLA printed at variable
infill can give, 1 ≤ εr ≤ 2.7, in 3 mm pixels: 2,250 design variables after the
feed's two mirror symmetries. At each step the optimiser takes the gradient of the
boresight directivity, averaged over 9.5, 10 and 10.5 GHz, with respect to every
pixel, through the FDTD solve and the far-field transform. Starting from a uniform block, the
descent grows a graded-index lens, εr 2.6 on the axis falling to about 1 at the
corners, and the boresight directivity at 10 GHz rises from 7.5 dBi for the feed
alone to 19.0 dBi. Solved again on 1.5, 1.0 and 0.75 mm meshes, the result moves by
0.03–0.05 dB over the last refinement; the gradient was checked against central
differences and against a 1.5× longer simulation. The dipole is driven as a soft
source, a current impressed on the grid with no feed line, and the lens is lossless,
so these are directivities, not realized gains.
[Read the case →](/rfx/showcase/grin-lens/)

## Where the gradient comes from

The gradient is the derivative of the simulated result itself, taken through every
time step. On a 2.3 GHz patch antenna, the value and the gradient over 43,008 design
cells take 1.4 times as long as the simulation alone.

## What the code looks like

The objective is an ordinary Python function of the permittivity in a design
box. JAX differentiates the whole time-stepping loop.

{/* rfx-showcase-objective:start */}

```python
...  # imports, board, corners, freqs, n_steps, checkpoint_segments, eps_bg: see the full script

def J(eps_box):
    res = board.sim.forward(
        design_box=corners, design_eps_override=eps_box,
        design_box_holds_ports=True, n_steps=n_steps, checkpoint=False,
        checkpoint_segments=checkpoint_segments,
        port_s11_freqs=freqs, skip_preflight=True)
    s = res.s_params[0, 0]
    return jnp.real(s[0]) ** 2 + jnp.imag(s[0]) ** 2

v, g = jax.jit(jax.value_and_grad(J))(eps_bg)
```

{/* rfx-showcase-objective:end */}

The full script builds the board, runs preflight once on it, and checks the
gradient against finite differences before anything is plotted.
[Full script →](https://github.com/bk-squared/rfx/blob/main/scripts/showcase/patch_sensitivity.py)

## Before you trust a number

A result holds for the structure, mesh and observable it was checked on. Read
[Support](/rfx/support/) before combining features, and check that
the [run is long enough](/rfx/check/simulation-time/) and the
[mesh fine enough](/rfx/check/mesh-convergence/) before reporting an RF result.
[Validation](/rfx/validation/) shows how rfx itself is checked.
