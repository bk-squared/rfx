# rfx Validation Scripts

These scripts compare rfx results with analytic calculations, other solvers,
or a second rfx configuration. They are test cases, not tutorials. Start with
`examples/README.md` if you are learning the software.

Each comparison covers the geometry, mesh, frequency range, source, and output
implemented by that script. A passing result does not establish accuracy for a
different setup.

## Run a validation case

Run scripts from the repository root, one case at a time:

```bash
python validation/crossval/07_sheen_lpf.py
```

The process exit code has a specific meaning:

- `0`: every configured numerical check passed, including a required external
  comparison when the case has one.
- `1`: a simulation, numerical check, or required execution step failed.
- `2`: the rfx checks completed, but a required reference file or external
  solver was unavailable. This result is inconclusive, not a pass.

See `crossval/manifest.json` for each script's dependencies, expected exit
codes, numerical-check files, and generated artifacts.

The original rfx leg (num_periods=20, default probe offset) was non-passive (58/120 bins, worst column power 1794.5) and its argmin sat 9.6% from OpenEMS; the root cause — record truncation (settling witness −24.7 dB) plus probe near-field contamination — was measured and the leg regenerated 2026-07-26 (num_periods=60, witness −72 dB; n_probe_offset=30, which satisfies both the 5·h_sub near-field and the λ_g/4 reflector clearances; passivity-enforced `\|S\|` strictly ≤ 1 with the raw excess recorded per bin). The current #931 sheet leg and derived referee were regenerated by VESSL 369367259192 (2026-09-07, commit 069bdebc): raw-bin rfx argmin 8.202 GHz vs OpenEMS 7.983 GHz (2.74% split), parabolic FDTD argmins 8.244069 / 7.994749 GHz. Both doublet members remain resolved (structure distance 2.87% vs OpenEMS 0.66%; sides_with = openems stands); the separately windowed argmin distance to Palace is 2.3756%, not the 2.8668% structure distance. Read narrowly still: `passivity_correction` > 0.05 occurs in 3/120 bins on the current leg (3/120, worst 0.6572 at 17.870 GHz), all three above 17 GHz and none inside the 5–15 GHz null band. This is the case's characterized high-frequency residual on a coarser realized strip at the same dx = 200 µm, not evidence of a physics regression in the stated null band; it is not a magnitude-accuracy claim — the pre-#516 leg's 84/120 bins, worst 0.365, was substantially extractor defects, not a coarse-mesh envelope — and the fitted passband `Re(Z₀)` reads 51.9 Ω vs OpenEMS's flat ~51 Ω (printed, not gated; the old ~67 Ω fit-conditioning residual is gone; the in-band 5–15 GHz median is 54.7 Ω); the null position is insensitive to this. Re-gated 2026-09-01 (issue #812 mechanism P3, `docs/design_notes/estimator_resolution_regate.md`): the committed null was a bin argmin on a 163.866 MHz grid (2.081%/bin) judged against a declared 1% window, so erasing the lower doublet member left every gated number bit-identical and passed 17/17. When reporting a result, include the script path, commit, geometry, mesh,
frequency range, comparator, and numerical thresholds. Do not generalize a
successful case to a different port, material model, boundary, or mesh without
an applicable comparison.

## Other validation directories

- `research/subgrid/12_subgrid_disjoint_prototype.py` is a short-duration
  research check for a topology that is not long-time energy-stable.
- `research/subgrid/13_subgrid_material_validation.py` demonstrates the guarded
  subgrid boundary and checks the same material setup on a uniform mesh.
  SBP-SAT/subgridding is not a supported feature.
- `tmtt_paper/` contains paper-support scripts. Values identified there as
  targets are experiment goals, not measured results. See
  `tmtt_paper/README.md` for the status of each script.
